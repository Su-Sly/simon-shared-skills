# 安全、生产与委派验收门禁

用于审核包含生产部署、服务重启、配置/数据库写入、备份恢复、外部通讯、跨Profile修改或委派整改的Skill。

## 1. 安全策略规避

出现以下可执行建议直接P0 FAIL：

- 工具/CLI被安全策略拒绝后，改用`execute_code`、subprocess、cron、watchdog、其他Profile或脚本绕过。
- 用宽泛`pkill`、`killall`、`kill -9`替代精确身份发现和授权。
- 主入口写禁止，但linked references/scripts/templates仍保留可复制的绕过路径。
- 把工具成功返回、进程Up或脚本自报success当作安全门禁通过。

正确修复：停止，报告拦截原因，转交经授权入口，并验证无授权/被拦截场景都会停止。

## 2. 高风险授权Checklist

备份创建、安装、证书、Git状态变化、构建、重启、API/数据库写入、删除/移动文件都属于状态变化：

- [ ] 精确列出对象、动作、影响范围和回滚。
- [ ] Simon下一条消息严格等于数字`1`后才执行清单内动作。
- [ ] 新增范围重新确认；旧授权不自动扩大。
- [ ] 删除不可恢复数据永不执行；可逆归档也需明确授权范围。
- [ ] 跨Profile写入只有用户明确指定目标Profile后才可启用`cross_profile=True`。
- [ ] 失败立即停止，不把部分成功简写为成功。

## 3. 生产示例

所有Shell围栏逐块跑`bash -n`。可执行示例应：

- 使用环境变量和缺值即停，不用Shell会解释为重定向的尖括号占位符；
- `set -euo pipefail`，检查命令失败阻止后续动作；
- `curl -f`并检查预期状态/内容；
- 部署前验证目标SHA来自权威远端分支，不能只用`git cat-file`证明本地存在；
- 服务active/容器Up后继续验证版本、health、真实业务入口和新日志；
- 外部前提缺失时标`production_runtime_verified=false`，Skill质量与生产状态分开。

## 4. 架构一致性

检查权威链路是否自相矛盾：

- 本地Git → 权威远端 → 服务器部署，不能同时教服务器直改、SCP/`docker cp`热补丁或生产机打tag。
- reset/drop/force/`--accept-data-loss`必须有备份、diff、数字确认和回滚。
- 官方工具/API/协议锚定官方文档与查证日期；不凭记忆写死契约。

## 5. 含secret备份

分别验收：

1. Archive：精确包含/排除、权限、一致性、本地hash。
2. Transport：TLS与上传成功。
3. Storage：ACL、最小权限、加密、密钥保管、版本/保留策略。
4. Remote integrity：对象size和真实checksum对账；sidecar存在不等于值已核对。
5. Recoverability：隔离恢复，拒绝路径穿越/链接/设备文件，数据库integrity和选择性激活。

控制缺失时不得称“安全备份”或“灾备完成”，也不主动复制更多secret到云端。

## 6. 委派整改验收

worker的PASS只是待验收自报。父Agent独立核对：

- before/after快照、全文回读、链接、围栏、脚本和运行时可见性；
- 12维名称、证据、fail/warn计数和verdict公式；
- 外部脚本、cron、配置、云对象或服务等明确可执行调用链；
- 内容质量与外部系统状态分轴；
- 大幅删减有章节映射、迁移路径、引用验证和知识保全证据。

只评估失真而文件未改时拒收结果；发生无证据删减时恢复该worker修改的文件。未完成复核前只能标“语义审核待完成”。

## 7. 完成证据

- 配置：回读字段和值。
- 进程：状态 + health + 新日志。
- 部署：目标commit/镜像 + 真实入口。
- 文件：路径、行数、字节、hash、内容回读。
- 备份：远端完整性 + 隔离恢复。
- 删除/归档：授权、原路径消失、目标存在、运行时仍正确。

验证失败时自动修复或明确阻塞，不得报告完成。
