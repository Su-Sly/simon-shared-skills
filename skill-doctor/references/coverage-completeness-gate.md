# 结果完整性与覆盖性门禁

适用于提取、摘要、批量审计、文件处理、分页搜索、长文档分析等任务。目标不是只证明“输出内容是真的”，还要证明“输入范围被完整处理，没有交付漂亮的残稿”。

## 1. 两类验证必须分开

| 门禁 | 回答的问题 | 常见证据 |
|---|---|---|
| 正确性（correctness） | 已输出的结果是否真实、格式正确、能回源 | 逐字引用、字段校验、hash、schema、API 回读 |
| 完整性（completeness） | 应处理的输入是否全部遍历，是否漏文件、漏分页、漏尾部 | 输入/输出集合差、游标终止、分页记录、分段覆盖、尾部哨兵 |

正确性全绿不能替代完整性验证。一条真实引用不能证明材料后半段已读。

## 2. Coverage Contract

任务存在长输入、分页、批量或多来源时，在执行前定义：

1. **Input Universe**：完整输入范围是什么（文件清单、record IDs、页数、章节、行区间、API 游标）。
2. **Traversal Evidence**：如何证明遍历完成（每段起止位置、最后游标、总数对账、每个 unit_id 的状态）。
3. **Completeness Check**：如何检测缺口（集合差、未处理列表、章节覆盖矩阵、尾部哨兵）。
4. **Exception Policy**：哪些空段/无命中可接受，豁免理由如何披露。
5. **Completion Rule**：范围不明、遍历证据缺失或存在未解释缺口时，不得报告完成。

## 3. 按任务类型选择证据

### 长文档提取/摘要

- 记录源文件总行数、字节数或章节数。
- 按工具可完整读取的上限分段，保存每段起止范围。
- 检查最后一段确实读取；必要时在测试材料首部、中部、尾部放已知哨兵。
- “某段无命中”只能说明结果稀疏，不能自动判定未读取；应结合遍历日志或哨兵。
- 不把固定“尾部 40%”阈值当普适规律。阈值必须针对任务说明依据。

### 批量审计/批处理

- 执行前冻结输入 ID 集合；完成后比较：`expected == completed ∪ failed ∪ explicitly_skipped`。
- 输出 unknown、duplicate、missing IDs 时判失败。
- 运行状态 `completed` 不等于结果完整，必须验证每个单元产物存在且可解析。

### 多文件转换/迁移

- 比较源文件清单与产物清单，单列排除项及理由。
- 对抽样产物验证内容，不只验证文件存在。
- 数量一致仍可能错配；必要时保存 source→target 映射与 hash。

### API/网页分页采集

- 记录每页/游标、返回数量、终止条件。
- 必须到达明确终点（空页、`next_cursor=null`、官方总数对账），不能因单页成功就宣布完成。
- 限流、超时或反爬中断应标为 incomplete，而不是返回已有部分并写成功。

### 搜索/汇总

- 明确来源范围与检索策略，不能把“搜索到的结果都真实”写成“已覆盖全部相关结果”。
- 无法证明穷尽时，输出应写“在已检索范围内”，并披露范围。

## 4. 评分器也要验收

- 被测 Agent 的“我已验证”不是独立证据。
- script judge / agent judge 的工作目录、可见文件、输入字段和退出码要用固定样本或探针验证。
- 首次 FAIL 先区分被测对象失败、评分脚本失败、环境路径失败。
- 修改评分器后，用已知 PASS 与已知 FAIL 样本各跑一次，防止只会亮绿灯。

## 5. Skill Doctor 审查规则

在第9维“质量标准与验证闭环”中检查：

- 输入是否可能分段、分页、批量或跨多个来源？
- 若是，Skill 是否定义 Coverage Contract 或等价证据？
- 产物校验是否只检查真实性/格式，却没有验证输入完整遍历？
- 豁免是否要求披露，还是允许静默跳过？

判定：

- ✅ 正确性与完整性均有可观察证据；或任务确实不存在覆盖风险并说明原因。
- ⚠️ 有遍历意图，但输入范围、终止条件或豁免披露不完整。
- ❌ 明显存在长输入/分页/批量风险，却只验证已输出内容；或允许部分结果冒充完成。

此门禁是第9维的横切检查，不新增第13维。
