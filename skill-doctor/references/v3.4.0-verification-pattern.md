# Skill Doctor v3.4.0 Quick Reference

## 验证闭环（Verification Pattern）

对涉及状态变更的 Skill，审核 5 元素：

| 元素 | 检查 |
|------|------|
| Action | 做了什么改变？ |
| Verification Target | 验证什么对象？ |
| Verification Method | 用什么方法？（curl/docker logs/读页面/查数据） |
| Success Criteria | 什么结果代表成功？（HTTP 200/无ERROR/数据一致） |
| Completion Rule | 未通过验证不得声明完成 |

## 批量审计流程

1. `find ~/.hermes -path '*/skills/*/SKILL.md'` — 列出所有 profile 的 skill
2. 按领域分组（维护类/部署类/工具类等）
3. 并行子任务审计（每组 2-3 个 skill）
4. 汇总 → 高频问题热力图（≥3 skill 同维度 ⚠️ = 系统性缺口）
5. 批量修复 → 每个修复用 skill_manage(action='patch')
6. 自验 → Phase 3B: skill_view 回读确认写入

## 关键 pitfalls

- **不要只搜 default profile** — skill 可能在 `~/.hermes/profiles/*/skills/` 下
- **不要改内置 skill** — `~/.hermes/hermes-agent/skills/` 下的是 Hermes 框架自带的
- **子任务报告格式可能丢失** — 子代理输出 "hello" 不代表没执行，用 `grep` 验证磁盘
- **references 存在性** — 引用的 references 文件必须实际存在，用 skill_view(name, file_path) 逐个验证
- **跨 profile 的 skill 不在同一个 git repo** — work-web profile 的 skill 改动需要单独处理

## 与维护 skill 的"修复后必须自验"规则关系

- 22 个维护 skill 已插入 `### 修复后必须自验` 规则（curl/docker logs 验证 → 附结果 → 不能验要说明）
- skill-doctor 维度 9 检查"被审 Skill 是否有验证闭环"
- 两者互补：skill-doctor 是审核工具，维护 skill 是被审核对象
